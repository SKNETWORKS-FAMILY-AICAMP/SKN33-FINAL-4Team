## 2. 평가 방법

### 2.1 실행

- 질문마다 `read()`와 같은 입력을 보냈다. `{"text": 질문, "pending": null, "context": {}}` 형식이고, 이전 대화가 없는 새 대화다. 라우터 해석은 회원 정보를 쓰지 않는다.
- 서비스와 같은 LLM 클래스(`chat.llm.live.LiveReading`)와 Structured Outputs 스키마를 썼다. 호출은 질문 하나에 한 번이다.
- 실행 순서
  1. 10건 시험 실행
  2. 기능별로 골고루 뽑은 20건으로 변환 확인
  3. 나머지 1,671건 실행 (11:36~12:32, `caffeinate`)
- 호출 수는 모두 1,701회다. 429가 없어서 다시 돌린 질문은 0건이다.
- 실행 스크립트는 `local_eval/router/run_router_eval.py`다. 이미 결과가 있는 id는 건너뛰므로 끊겨도 이어서 실행된다.

### 2.2 출력 변환표

| 라우터 출력 | predictions 칸 |
|---|---|
| intents: spending / budget_adjust / policy / unsupported / unclear | 소비분석 / 예산조정 / 청년정책 / 범위밖 / 확인질문 |
| intents의 첫 번째 | `agent` |
| intents 전체 | `agents` |
| direction: up / down | `slots.action`: 늘리기 / 줄이기 |
| categories (FOOD → 식비 등, 시드 이름, UNCLASSIFIED → 미분류) | `slots.category` (여러 개면 목록) |
| categories의 `{"unknown": 원문}` | `slots.category`: `"미인식:원문"` |
| amount | `slots.amount` |
| amount_mode: by / to | `slots.amount_mode` (그대로, 비율 값은 없음) |
| 라우터 원래 출력 전체 | `raw` |

- 슬롯은 `agent`가 예산조정일 때만 넣었다. 다른 기능은 `{}`다.
- 형식 실패(`format_ok: false`)로 본 경우는 세 가지다. JSON이 아님, 서비스 `parse()`의 형식 검사 실패, intents에 변환표 밖 값이 있음. 실제로는 0건이었다.
- unknown 카테고리 규칙은 실행 도중에 바뀌었다. 처음에는 agent=null, format_ok=false로 처리했고, 나중에 `"미인식:원문"`으로 바꿨다. 실행이 끝난 뒤 라우터를 다시 부르지 않고 저장된 raw로 다시 변환했고, 26줄이 바뀌었다. 원본은 `predictions.jsonl.bak`에 있다.

### 2.3 채점 기준 (score_router.py)

- **연결 정확도:** `agent`가 정답 기능과 같은 비율.
- **허용 포함:** 허용 적용이 Y인 질문의 허용 기능, 잡담 메모가 있는 질문의 범위밖까지 정답으로 인정한 비율.
- **슬롯 채점:** 예산조정 중 정답 action이 늘리기 · 줄이기인 질문만 대상이다. action · category · amount를 비교한다.
  - 라우터는 "옮기기 · 큰지출대비"를 표현할 수 없어서, 이 질문들은 슬롯 채점에서 뺐다(옮기기 116건, 큰지출대비 64건, action 없음 39건).
- **amount:** 정답이 비율인 질문은 채점하지 않는다. 단 "0원으로 · 다 빼줘"(줄이기 + percent 100)는 amount 0 + amount_mode to면 정답이다. 그 밖에는 금액이 같고 amount_mode가 to가 아니어야 정답이다.

## 5. 키워드 기준선

- 규칙은 기획안 3장 핵심 기능 표와 기능 설명만 보고 한 번에 정했다(`local_eval/router/baseline_keywords.py`). 위에서부터 처음 걸리는 규칙을 쓴다.
  - 청년정책: 지원 · 혜택 · 정책 · 제도 · 청년 · 청약 · 장학 · 자격 · 신청
  - 예산조정: 늘려 · 줄여 · 옮겨 · 올려 · 낮춰 · 조정 · 다시 짜 · 재분배 · 바꿔
  - 소비분석: 얼마 · 썼 · 쓴 · 남은 · 지출 · 소비 · 내역 · 분석 · 비교 · 합계 · 총액
  - 예산조정: "예산"만 있을 때
  - 범위밖: 주식 · 종목 · 코인 · 투자 · 날씨
  - 그 밖: 확인질문
- 결과는 연결 정확도 58.0%다. 유형별로는 직접 65.2%, 간접 38.8%, 상황 12.0%다.
- 틀린 것 대부분은 키워드가 하나도 안 걸려 확인질문으로 간 경우다(639건).
- 라우터와의 차이(+39.2%p)는 간접 · 상황 질문에서 가장 크다(간접 +58.9%p, 상황 +81.0%p).
- 한계: 이 규칙은 평가셋 일부(시험 실행 30건, CSV 요약)를 본 뒤에 만들었다. 평가셋 문장을 규칙에 쓰지는 않았지만, 평가셋을 전혀 모르는 상태에서 만든 기준선은 아니다.

## 6. 해석할 때 주의할 점

- **단일 턴 평가다.** 질문마다 새 대화로 보냈으므로, 후속 질문 · 라우터가 되묻는 중의 답 · 진행 중 예산 조정 같은 맥락 처리는 평가하지 않았다.
- **1회 실행이다.** 같은 질문을 다시 보냈을 때 결과가 흔들리는 정도는 재지 않았다.
- **슬롯 점수는 라우터 원래 출력 기준이다.** 서비스 `parse()`는 예산조정만 요청한 경우 보조값 형식이 틀리면 보조값을 통째로 버린다. 예를 들어 amount 없이 amount_mode만 있는 출력이 9건 있었다. 서비스에서는 이 9건의 category · action도 에이전트에 전달되지 않는다.
- **채점 대상이 아닌 슬롯이 있다.** 옮기기 · 큰지출대비 · 비율 금액은 라우터 출력 형식에 칸이 없어 채점하지 않았다. 이 부분의 최종 해석은 예산 조정 에이전트가 한다.
- **소비분석 · 청년정책 슬롯은 라우터가 내지 않는다.** 각 에이전트 평가에서 따로 봐야 한다.

## 7. 개선 후보 (검토용, 이번 평가에서 적용하지 않음)

1. **범위밖과 청년정책의 경계를 정하기.** 진로 상담 · 재테크 방법 · 보험 가입 판단 · 인사말을 어디로 보낼지 프롬프트와 평가셋 기준을 맞춘다. 범위밖 오답 19건의 대부분이 여기에 해당한다.
2. **여러 기능일 때 순서 정하기.** "비용 부담 + 예산 늘려줘"처럼 조정을 직접 요청하면 budget_adjust를 앞에 두도록 한다. 또는 서비스가 agents 전체를 쓰는지 확인한 뒤 채점 기준을 정한다.
3. **"전부 빼기 · 0원으로"를 amount 0 + to로 내게 하기.** 슬롯 오답의 절반(12건)이 여기에 해당한다.
4. **"분류 안 된 항목"의 기준 정하기.** 기타(ETC)인지 미분류(UNCLASSIFIED)인지 정한다. 서비스 규칙상 UNCLASSIFIED는 예산 카테고리가 아니라서, 예산 조정에서는 기타가 맞을 가능성이 높다.
