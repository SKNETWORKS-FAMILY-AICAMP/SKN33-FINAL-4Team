# 청년 정책 추천 에이전트

통합 챗봇에서 사용자의 고민과 조건을 받아 맞는 청년 정책을 추천한다. 온통청년 정책 3,664건을 미리 정리 · 임베딩해 두고(RAG), 질문마다 검색 → 자격 확인 → 돌아보기를 거쳐 답한다.

**원칙: 판단은 LLM, 사실은 코드.** 정책명 · 기간 · 금액 · 링크 · 자격 판단은 코드가 DB 값으로 채우고, LLM은 질문 읽기 · 다음 행동 고르기 · 맞는 정책 고르기만 한다.

## 1. 흐름

```
① 미리 (sync_policies)
   정책 원본 → 칸 정리(normalize) → 임베딩 → pgvector 저장

② 질문마다 (policies/agent.py)
   읽기       문장 → 찾는 지원(검색 문장 + 키워드) 최대 3개 · 지명 · 막연한지   [LLM 1회]
   행동 고르기 검색 / 되묻기 / 정책 상세 / 다른 담당 / 끝내기                  [LLM 1회]
   검색       지역 · 마감을 SQL로 거르고, 벡터 순위와 키워드 순위를 RRF로 합침
   자격       나이 · 성별 · 지역 · 취업 상태 등으로 불충족 정책 빼기             [코드]
   돌아보기   앞 10개를 질문과 비교해 맞는 것만 남김 (0~10개)                  [LLM 1회]
   답변       정책 카드 (사실은 DB 값) + "자격 확정이 아니에요" 안내
```

한 턴의 도구 호출은 정해 둔 도구만, 최대 횟수 안에서 한다. 추천 번호는 도구 결과 안에서만 고를 수 있다(코드가 검사).
`CHAT_LLM=fake`이면 LLM 판단 없이 규칙 흐름으로만 동작하고, 질문 임베딩이 가짜라 검색 결과는 의미가 없다.

## 2. 정해진 규칙

**조건 입력 (별도 화면 없이 채팅에서)**
- 나이 · 성별은 내 정보(생년월일 · 성별)를 쓴다. 생년월일이 없으면 내 정보 입력으로 안내하고 끝낸다.
- 찾을 지역: **문장 속 지역 > 사는 곳(내 정보) > 지역 버튼**. "서울"처럼 넓으면 그 안의 시군구만, "중구"처럼 여러 곳이면 후보만 버튼으로 묻는다. 다른 지역으로 찾으면 [다음에도 ○○구로 찾기]로 사는 곳을 바꿀 수 있다.
- 취업 상태: 월급 정보가 있으면 재직자로 보고, 대화에서 말한 상태가 있으면 그것을 따른다.
- 묻지 않는 것: 학력 · 전공 · 혼인 · 주거 형태 · 연소득. 이런 요건이 있는 정책은 '확인 필요'로 표시한다.

**자격 판단 (코드, 위에서부터 처음 맞는 줄)**

| 순서 | 경우 | 결과 |
|---|---|---|
| 1 | 정책 조건이 제한 없음 | 충족 |
| 2 | 정책 칸이 비었거나 사용자 값을 모름 | 확인 필요 |
| 3 | 사용자 값이 정책 조건에 있음 | 충족 |
| 4 | 정책 조건에 '기타'가 있음 | 확인 필요 |
| 5 | 그 밖 | 불충족 (추천에서 뺌) |

- 지역은 코드를 그대로 비교하지 않고 지역별 `match` 목록으로 비교한다(시 코드로만 등록된 구 정책 등).
- 소득은 탈락 근거로 쓰지 않는다(금액 단위 · 본인/가구 구분을 알 수 없음).
- 나이는 숫자 범위를 쓰고, 추가 자격 원문의 "NN~NN세"와 어긋나면 둘을 모두 감싸는 넓은 범위로 본다.

**검색**
- 후보는 신청 중 · 상시 · 신청 예정 · 기간 모름. 마감 · 신청기간이 지난 정책은 뺀다. 사업 종료일이 지난 상시 정책은 빼지 않고 표시한다.
- 키워드는 정확한 부분 문자열로 찾는다. 벡터만으로는 놓치는 정책을 키워드가 메운다(아래 평가).
- 찾는 지원이 둘 이상이면 필요마다 따로 검색해 RRF로 합친다.
- 같은 기관의 재등록 정책은 추천 3칸이 겹치지 않게 하나만 보인다.

**돌아보기 · 답변**
- 돌아보기는 목적과 지원 내용의 관련이 명확한 후보만 남긴다. 3개를 억지로 채우지 않고, 맞는 게 없으면 "찾지 못했어요"라고 답한다. 없는 정책 이름을 지어내지 않는다.
- 돌아보기 호출이 실패하면 검토 안 된 후보를 보여 주지 않고 다시 시도를 안내한다.
- 모든 추천에 "자격 확정이 아니에요. 공고 원문으로 확인해 주세요."를 붙이고 "신청 가능"이라고 쓰지 않는다.
- 정책 카드: 한 번에 한 정책, 이전 · 다음으로 넘김. [자세히 보기]는 지원 내용 · 신청 방법 · 제출 서류 · 기간 · 자격을 DB 원문으로 보여 준다. [저장]은 `PUT /api/policies/<정책번호>/saved/`([API](../api/policies.md)).

**대화**
- 추천 뒤에도 담당을 유지해 "그거 신청 링크 알려줘" 같은 후속 질문에 답한다. "그거"는 방금 상세를 본 정책이다.
- 소비 · 예산 질문은 상태를 바꾸지 않고 라우터로 돌려보낸다(`not_mine`). 다른 담당을 다녀오면 [이어서 하기] [새로 추천]을 묻는다.
- 핸들러는 DB에 쓰지 않는다. 사는 곳 저장(`save_profile`)은 채팅 엔진이 대화 저장과 같은 트랜잭션에서 한다.

## 3. 구성

| 무엇 | 위치 |
|---|---|
| 데이터 적재 · 임베딩 · 정리 | `policies/sync.py` · `normalize.py` · 명령 `sync_policies` · `policy_renormalize` |
| 질문 읽기 | `policies/reading.py` (`read`) |
| 행동 고르기 | `policies/planner.py` (`ask`) — LangChain Core 체인, 실패하면 규칙으로 |
| 검색 | `policies/search.py` (`search` · `search_needs`) |
| 자격 | `policies/eligibility.py` (`judge` · `keep`) |
| 돌아보기 | `policies/review.py` (`keep`) |
| 도구 (조건 · 찾기 · 상세 · 사실) | `policies/tools.py` |
| 핸들러 (라우터 계약 `handler(request) → dict`) | `policies/agent.py` (`handle` · `decide`) |
| 지역 | `policies/regions.py` · `policies/data/regions.json` |
| 저장한 정책 · 지역 API | `policies/saved.py` · `policies/api.py` |
| LLM 호출 | `policies/llm.py` — 라우터와 같은 `ResponsesClient`(호출 상한 · JSON 형식 강제)를 LangChain Core 체인에 넣어 쓴다. LangGraph는 쓰지 않는다 |

## 4. 정책 데이터 준비

정책 데이터는 저장소에 없다. 없으면 정책 추천은 "찾지 못했어요"로만 답하고, 소비 분석 · 예산은 그대로 동작한다.

**A. 적재가 끝난 덤프로 복원 (임베딩 비용 없음)**

```bash
docker exec -i money-cushion-db pg_restore -U money_cushion -d money_cushion --data-only --no-owner < policies.dump
docker exec -i money-cushion-db psql -U money_cushion -d money_cushion -tAc "select count(*), count(embedding) from policy;"   # 3664|3664
```

덤프는 `policy` · `policy_sync` 두 표의 데이터만 담는다. 이미 정책이 있으면 키 충돌이 나므로 `TRUNCATE policy, policy_sync;` 후 다시 복원한다(저장한 정책이 있으면 막힌다). 덤프 만들기: `pg_dump --data-only --no-owner -t public.policy -t public.policy_sync -Fc`.

**B. 원본 파일에서 적재 (약 40초, OpenAI 임베딩 약 100만 토큰)**

```bash
cd backend
python manage.py sync_policies --file <온통청년 정책 JSON> --data-date 2026-10-29 --live-embed
python manage.py policy_renormalize --save    # 정리 규칙을 바꾼 뒤 저장된 원본으로 다시 정리 (임베딩은 그대로)
```

실행에는 `CHAT_ENGINE=router` · `CHAT_LLM=live`와 `OPENAI_API_KEY` · `LLM_MODEL` · `EMBEDDING_MODEL`(적재 때와 같은 모델, `text-embedding-3-small`)이 필요하다([환경변수](../ENV_SETUP.md)).

## 5. 확인 · 평가

```bash
cd backend
python manage.py policy_search "자격증 시험비가 너무 비싸" --region 관악구 --read --live-embed   # 질문 읽기 + 검색 결과 보기
python manage.py policy_chat "[버튼]" 서울특별시 관악구 "자격증 시험비가 너무 비싸"   # 대화 흐름 보기 ([버튼] = 청년 정책 기능 버튼)
python manage.py policy_eval [--auto]          # 정답 문제 채점 (policies/eval/)
python manage.py test policies                 # 자동 테스트
```

**검색 평가** — 정답이 있는 질문 18개, 기준일 2026-11-10 (`policies/eval/questions.json`, 채점 방법은 [eval README](../../backend/policies/eval/README.md))

| 방식 | Hit@3 | Hit@10 | 30위 안 | MRR |
|---|---|---|---|---|
| 벡터만 | 16.7% | 66.7% | 77.8% | 0.194 |
| 벡터 + 사람이 고른 키워드 | 66.7% | 88.9% | 100.0% | 0.596 |
| 벡터 + LLM이 읽은 키워드 (서비스 방식) | 55.6% | 94.4% | 100.0% | 0.583 |

- 키워드를 합치면 Hit@3가 3~4배 오른다. 서비스는 LLM이 문장에서 키워드를 뽑는다.
- 18문제라 한 문제가 5.6%p다. 프롬프트끼리의 차이는 여러 번 돌린 평균으로 봐야 한다.
- 벡터 거리만으로는 '맞는 정책 없음'을 가를 수 없어서, 돌아보기 단계가 맞는 것만 남기고 없으면 "찾지 못했어요"라고 답한다.

## 6. 한계

- 데이터 기준일이 2026-10-29(파일 적재)이라 이후 공고는 없다. 온통청년 API 자동 수집은 아직 붙이지 않았다.
- 지역 코드가 200개를 넘는 정책은 '전국'으로 표시하지만, 실제로는 지자체 사업이 섞여 있다.
- 말하지 않은 대상 조건(신혼부부 · 군인 등)에 해당해도 대상 전용 정책은 빠질 수 있다(조건을 묻지 않기로 했기 때문).
- 나이 칸이 빈 정책은 실제 나이 조건을 원문으로 확인해야 한다.
